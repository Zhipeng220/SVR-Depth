# SVR-Depth Y04-V4 Bonn18 物理环境审计结论

**审计日期：2026-11-08**  
**输入：** 用户上传 `y04_v4_physical_scene_audit_20261108_codex.zip` 中的 18 个序列三帧图、`sequence_metadata.csv` 和 `cross_split_pairs.csv`。

## 结论

- **原计划 TRAIN13 / DEV5 不具备“独立物理场景验证”证据；不允许声称 cross-scene generalization。**
- 所有 18 条序列代表帧均出现高度一致的实验室风格与固定设施（长桌、黑色/浅色椅、墙面插座排、仪器平台）；多组 TRAIN/DEV 具有清楚对应的固定背景。跨集合静态环境重叠**高度可信**，保守研究处理应将这些录像视为共享环境。
- `groundtruth.txt` 各自存在，但此包未包含完整逐帧位姿原始数据，只有数值范围，不足以验证统一世界坐标，也不足以证明录制绝对位置相同。
- Bonn 官网同时提供单份静态环境 GT 点云，但不能仅由此断言所有录像无条件共享每一处空间。官方资料：https://www.ipb.uni-bonn.de/data/rgbd-dynamic-dataset/

## 对研究主张的影响

1. 当前 13/5 分组可以作为 **same-environment sequence-disjoint development**，但不能被称为 physically independent scene held-out / zero-shot Bonn。
2. 如果用 Bonn13 训练，则 Bonn 数据集测试不再是 zero-shot；Bonn 论文 protocol 可另报 benchmark，但需列出与训练/开发重叠的序列并如实说明 contamination。
3. 如果 CVPR 主实验要保留 Bonn zero-shot 结论，主模型的头部训练与 checkpoint 选择不能使用 Bonn，且应复核底座预训练与基准协议重叠。
4. 当前建议**允许在明确“Bonn域内适配、序列级开发”的限定下推进工程化单种子训练**，但正式开跑前应把 split 名称、验证使用方式、Bonn3/Bonn13 公平训练预算与确定性/恢复环境固定到 run identity。不要越级将模型宣称跨场景泛化。

## 验收状态

| 检查 | 判定 |
|---|---|
| 数据解码与候选配对 | 通过既有审计 |
| Bonn13 13-step 多序列开发训练 | 用户报告通过，日志未在此次 ZIP 内 |
| 物理场景独立性 | **不支持，研究上按同一实验室环境处理** |
| 正式训练的统一入口 + 恢复确定性配置 | 需锁定 |
| 零样本 Bonn 主实验 | 不能由 Bonn13 训练权重支持 |

## 局限

- 只审阅 10%/50%/90% 帧，不能排除未采样帧中的空间差异。
- `scene_id` 需要原始录制元数据、完整相机轨迹及场景地图或摄影测量配准最终确认；这里使用的是保守阻断逻辑，不是精确场景注册。
- 视频中相同家具/人并不保证每条序列相同时间或视角，故场景独立统计不得假设 18 个独立样本。
